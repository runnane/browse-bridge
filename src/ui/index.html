    browse-bridge Help
    
    
    
      
    What it does
    
      
    browse-bridge lets AI agents on a remote dev host drive the browser on this machine. It keeps an SSH tunnel from here to the
        browse relay on each remote host, and the browse extension in your browser connects through it. Nothing listens on the
        remote host beyond loopback, and the link rides inside SSH.
    

      
    First run
    
      
      
        
    1. On the Settings tab, enter the SSH host (user@host or an ~/.ssh/config alias without a LocalForward) and click Apply.
          The app never prompts for a password: use key-based ssh (an agent, or IdentityFile under SSH options).
      2. 
        
    2. Click Set Up Host. It installs the pinned browse () on the remote, turns auto-update off,
          binds the relay to loopback and checks all of it there. Expect a "Host verified" message.
      3. 
        
    3. Install the OpenCode Browse extension in Edge or Chrome.
      4. 
        
    4. Click Pair Browser… and enter the code and the address it shows in the extension's options
          (advanced or Pair with a code), then click Connect there.
      5. 
        
    5. The host shows Connected. Agents on the remote use it through the browse MCP server.
      6. 
      
    

      
    Several hosts
    
      
    Add Host… under the host list adds another; Remove Host… on the Settings tab drops the selected one.
        The toolbar and every tab act on the host selected in the list. Each host has its own pairing address
        (localhost, 127.0.0.2, …, on the relay's port).
        A browser profile follows one host at a time: to switch, enter the other host's address in the extension.
        To use two hosts at once, pair a second profile or browser.
    

      
    What the states mean
    
      
    
        
    Connected
    Tunnel up, relay running, a browser connected.
    
        
    Connected, with warnings
    Working, but auto-update is on or a browse version other than the pinned one is running. The warning shows in a bar above the tabs; Set Up Host fixes both.
    
        
    Browser not connected
    The bridge is up but no browser is connected: click Pair Browser…, or point the extension at this host's address.
    
        
    Relay not running
    Since browse 0.1.4 the relay no longer shuts itself down when idle, so this means something went wrong: it crashed, was stopped, or the host rebooted. Click Restart Relay; if it does not come back, the Log tab (relay log) says why.
    
        
    Connecting
    The tunnel is starting.
    
        
    Tunnel down
    ssh failed or dropped; it retries with backoff. The Log tab says why.
    
        
    Stopped
    Not connected: click Connect.
    
        
    No host configured
    Enter an SSH host on the Settings tab.
    
        
    Unknown
    The status could not be measured, so it is not shown as healthy.
    
      
    

      
    Tabs and tray
    
      
      
        
    • Status: tunnel, relay, browser, agent tabs and auto-update for the selected host.
      • 
        
    • Traffic: bytes, rate and connections; with Count browser actions ticked in Settings, the names of the commands sent to the browser (never their contents).
      • 
        
    • Log: this host's lines, all hosts, or the remote relay log. Open Log File opens the full log.
      • 
        
    • Settings: the selected host's ssh destination, address and options. Its relay port and remote browse path are under Advanced.
      • 
        
    • General, below the host list: settings for the whole app. These are Start browse-bridge at login, the Status poll interval and the pinned browse version. Open Config File opens config.json for anything the window does not edit.
      • 
      
    
      
    Closing the window keeps the tunnels running in the tray. The tray menu has each host's own controls and Quit.
